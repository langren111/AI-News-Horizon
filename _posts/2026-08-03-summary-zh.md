## [Karpathy 点赞 sqliteai/waste：在 NVMe 上流式运行 2.78 万亿参数 Kimi K3](https://github.com/sqliteai/waste) ⭐️ 7.0/10

Andrej Karpathy 点赞了 GitHub 项目 sqliteai/waste，该项目是一个推理引擎，通过直接从 NVMe 流式传输激活的权重，在可用内存之外运行完整的 2.78 万亿参数 Kimi K3 模型。该项目是一个无依赖、可嵌入的 C 推理引擎。 Karpathy 的点赞凸显了在消费级硬件上运行大规模 AI 模型的日益增长的兴趣，可能使最先进模型的访问民主化。这可能影响 AI/ML 社区探索内存高效的推理技术和轻量级数据管理解决方案。 Kimi K3 模型发布时大小为 1.42 TB，转换后为 982 GB，无法容纳在当前主流消费系统的 RAM 中。该项目直接从 NVMe 流式传输激活的权重，从而在 RAM 限制之外进行推理。

github · karpathy · 8月2日 17:19

**背景**: 像 Kimi K3 这样的大型语言模型拥有数万亿参数，需要巨大的内存，超出了典型消费级硬件的容量。传统推理需要将整个模型加载到 RAM 中，但从存储（如 NVMe）流式传输权重允许在内存有限的系统上运行此类模型。Karpathy 是一位杰出的 AI 研究员，经常关注创新的开源项目，他的点赞可以显著提升项目的知名度。

## [Kakehashi：在 Linux ARM 上运行 macOS 二进制的用户空间层](https://github.com/wie-project/kakehashi) ⭐️ 7.0/10

Kakehashi 是一个实验性的用户空间翻译层，能在 Linux aarch64 上原生运行 macOS ARM64 命令行二进制文件，目前已为 7-Zip、curl 和 Git 提供了可工作的原型。它避免使用内核模块和 JIT，采用惰性桩（lazy stubbing）方法。 该项目填补了跨平台兼容性的重要空白，可能使 macOS 命令行工具无需模拟即可在 Linux ARM 上运行。如果成功，它可以补充 Darling 等现有解决方案，并扩展基于 ARM 的 Linux 用户的生态系统。 当前原型显示 7-Zip 的运行速度比原生 Linux 慢约 5.2 倍，但已有优化计划来缩小差距。curl 在自动化 Docker 测试中通过了 200 多个命令和选项，Git 支持基本版本控制。该项目以 CLI 为主，尚不支持 GUI 应用或代码签名/公证。

hackernews · vlad_kalinkin · 8月2日 16:26 · [社区讨论](https://news.ycombinator.com/item?id=49145937)

**背景**: 在 Linux 上运行 macOS 二进制文件一直是一个长期挑战，Darling 是最著名的翻译层，类似于 Windows 的 Wine。苹果的 Rosetta 2 允许 Intel 二进制文件在 Apple Silicon 上运行，但没有官方方法在 Linux 上运行 macOS 二进制文件。Kakehashi 采取了不同的方法，专注于用户空间和惰性桩，避免内核模块和 JIT 编译。
